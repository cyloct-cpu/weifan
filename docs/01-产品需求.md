# 产品需求

## 1. 用户与场景

**唯一用户**：你（中文母语，用 WhatsApp 与海外客户/供应商沟通）。

**典型场景**：

| 场景 | 现状的痛 | 微翻要做的 |
|---|---|---|
| 给墨西哥客户报交期 | 开 Google 翻译网页，复制粘贴，再复制回来发出去 | 打完中文点一下「译」，原地变成西语 |
| 客户发来一段 40 秒西语语音 | 完全听不懂，只能回 "Sorry, English please" | 长按分享给微翻，看到中文摘要 |
| 客户发来长段投诉 | 逐句翻译，语义散架 | 整段交给大模型，保持语气 |
| 报价里出现金额、型号 | 机翻把 1200 译成 1,200 或者干脆换算 | 金额硬拦截确认，型号用黑名单锁住 |

## 2. 核心用户故事

- **US-1**：作为用户，我在 WhatsApp 输入框里打完中文后，切到微翻键盘点「译」，输入框里的中文立刻变成对方语言，我确认无误后自己按发送。
- **US-2**：作为用户，对方发来外语消息，我长按 → 分享 → 微翻，2 秒内看到中文译文，并可一键复制。
- **US-3**：作为用户，对方发来语音消息，我分享给微翻，看到语音的中文译文。
- **US-4**：作为用户，我可以点键盘顶部的语言芯片，强制这次发西班牙语，而不是让系统猜。
- **US-5**：作为用户，我报价时如果句子里有金额，微翻会先把译文给我看一眼，我不点第二次它不会替换。
- **US-6**：作为用户，我给某个客户设了「只发西语、正式语气」，聊到他时点一下「客户」按钮即可套用。

## 3. 交互流程

### 3.1 发件（主路径）

```
在 WhatsApp 输入框用系统拼音键盘打字
        ↓
点地球键 → 切到「微翻」
        ↓
微翻显示：输入框现有中文 + 检测结果 + 目标语言
        ↓
点「译」
        ├─ 无风险 → 删除原文、插入译文 → 状态条提示"点绿色发送键"
        └─ 有硬风险（含金额）→ 显示译文 + 风险原因 → 再点一次「译」才替换
        ↓
点 WhatsApp 自己的绿色发送键
```

**撤销**：点「撤销」把译文换回中文（只保留最近一次）。

### 3.2 收件（文本）

```
WhatsApp 里长按对方消息 → 分享 → 微翻
        ↓
分享扩展弹出卡片：原文（灰）、译文（大）、来源语言 + 引擎
        ↓
自动复制译文到剪贴板（可关）→ 关闭 → 回到 WhatsApp 粘贴
```

### 3.3 收件（语音）

```
长按语音消息 → 分享 → 微翻
        ↓
"正在转写语音…" → Whisper 转写 → 翻译成中文 → 显示 + 复制
```

### 3.4 键盘上的信息层级

```
┌────────────────────────────────────┐
│ [自动] [EN] [ES] [PT] [FR] [AR] …  │ ← 语言芯片，蓝色为选中
├────────────────────────────────────┤
│ 这批货下周能发出吗？               │ ← 输入框里的原文（2 行）
│ 检测：中文 · 目标：西班牙语（兜底） │
├────────────────────────────────────┤
│ 输入框里是中文时，点「译」         │ ← 状态条
├────────────────────────────────────┤
│  [ 译 ]  [撤销]  [客户]  [切回]    │
└────────────────────────────────────┘
```

## 5. 第一版（v0.1）边界

**做**：F-01 ~ F-12。

**明确不做**：
- 自动发送（永远由人按最后一下）
- 修改或越狱 WhatsApp
- 云端账户体系、跨设备同步
- 群发、定时消息、CRM
- 图片 OCR、群聊优化
- 除 iOS 外的任何平台

## 6. 验收标准

按顺序在真机上验证，全过才算 v0.1 完成：

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A-1 | 键盘能装上并出现在键盘列表 | 设置里能看到「微翻」，可添加 |
| A-2 | 允许完全访问后能联网 | 输入中文点「译」，2 秒内出现译文 |
| A-3 | 替换正确 | 输入框里中文被完整删除、译文完整插入，无残留字符 |
| A-4 | 撤销正确 | 点撤销后恢复成原文，再次点译仍成功 |
| A-5 | 语言芯片生效 | 点 ES 后目标显示西班牙语，译文为西语 |
| A-6 | 金额拦截 | 输入「报价 1200 美元」点译，出现风险提示且**不**替换；再点一次才替换 |
| A-7 | 术语保护 | 黑名单里有「轻舟 Pro」，译文中保留原文，不出现 Light Boat |
| A-8 | 长句走大模型 | 输入 80 字长句，译文质量明显优于机翻，设置页可见 provider 为 LLM |
| A-9 | 分享扩展 | 在 WhatsApp 长按外语消息分享给微翻，显示中文译文 |
| A-10 | 语音 | 分享语音消息，显示转写后的中文译文（若 V-02 不成立则改为 App 内录音测试） |
| A-11 | 降级不崩 | 断网时点译，显示错误提示，键盘不崩溃、不退出 |
| A-12 | 冷启动速度 | 从切键盘到可点「译」小于 400ms |

## 7. 非功能需求

| 项 | 指标 | 理由 |
|---|---|---|
| 端到端延迟 | 机翻路径 ≤ 800ms，大模型路径 ≤ 3s | 超过 3 秒用户会切回手动翻译 |
| 键盘内存占用 | < 40MB | 扩展超过约 60MB 会被系统杀 |
| 键盘冷启动 | < 400ms | 键盘卡顿会直接影响打字 |
| 崩溃率 | 0（自用标准） | 崩一次就丢一次输入框内容 |
| 离线行为 | 明确报错，不静默失败 | 静默失败会让用户以为发出去了 |
| 隐私 | 不建服务器、不留云端记录、历史仅本地 200 条 | D-10 / D-16 |

## 8. 语言覆盖优先级

按真实跨境外贸沟通频次排序，`LanguageCode.sendTargets` 全部支持，但产品重心在 P1：

- **P1**：英语、西班牙语、葡萄牙语、法语、阿拉伯语、俄语
- **P2**：德语、意大利语、印尼语、越南语、土耳其语、泰语
- **P3**：荷兰语、波兰语、马来语、印地语、日语、韩语、希伯来语、菲律宾语

> 语言检测的准确度与语言在 `LanguageDetector.swift` 里的停用词表直接相关。P2/P3 语种的表较薄，短句误判率明显更高——这是已知且可接受的取舍（兜底英语）。
