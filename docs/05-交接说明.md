## 3. 下次开工的第一件事

```bash
brew install xcodegen
cd ios && xcodegen generate
```

然后在 `ios/project.yml` 里填 `DEVELOPMENT_TEAM`，`open WeiFan.xcodeproj`，选真机，编译。

**预期会有编译错误**，最多的是这几类，按概率排序：

1. `WeiFanCore` 的 `Package.swift` 平台声明与 Xcode 版本不匹配（改 `platforms` 即可）；
2. `AppSettings` 的 `CodingKeys` 在自定义 `init(from:)` 下未生成 → 显式声明 `enum CodingKeys: String, CodingKey`；
3. 键盘里 `UIButton.Configuration` 的 `titleTextAttributesTransformer` 闭包签名；
4. `ShareViewController` 里 `items.compactMap(\.attachments).flatMap { $0 }` 的类型推断；
5. SwiftUI 的 `.onChange(of:)` 在 iOS 17 改成了双参数闭包（代码里用的是旧的单参数，iOS 16 目标下正确，但 Xcode 15+ 会警告 deprecated）。

**不要急着加功能**，先把 A-1 到 A-4 跑通。

## 5. 代码约定

- **注释写"为什么"，不写"是什么"**。中文注释，面向未来接手的人。
- `core` 里禁止 `import UIKit` / `SwiftUI`。这是移植的唯一保障（D-12）。
- 所有面向用户的文案用中文；代码标识符用英文。
- 新增"风险原因"必须加进 `RiskReason` 并实现 `displayName`，否则键盘上的提示会显示英文 rawValue。
- 改提示词（`LLMTranslationProvider.systemPrompt`）必须回归 A-6 / A-7。
- 改 `SendOutcome` 字段等于改四端契约，需在 `docs/00-决策记录.md` 追加一条 ADR。

## 6. 已知坑（别人踩过的）

| 坑 | 表现 | 处理 |
|---|---|---|
| 先删原文再翻译 | 翻译失败时输入框空了，用户白打一段话 | **永远先拿到译文再删**，当前实现已如此，不要为了省 100ms 调换 |
| `deleteBackward` 用 `utf16.count` | 中文/emoji 删不干净，残留字符 | 用 `String.count`，并封顶 2000 |
| 键盘扩展读历史记录 | 内存涨到 60MB 被系统杀，表现为"键盘突然消失" | 键盘里不碰 `TranslationHistory` |
| 分享扩展里直接用临时 URL | 回调返回后文件已被删除，上传 404 | 先 `copyItem` 到 temp 目录（已实现） |
| 把密钥写 UserDefaults | 明文可被备份导出 | 一律走 Keychain |
| 语言检测拿整段历史当输入 | 检测结果被上一句带偏 | 只传"最近一条对方消息"作为 `contextSample` |
| 在键盘里做边打边译 | 每停顿一次一次请求，费用与延迟双爆 | 只在点「译」时请求（D-04 的隐含收益） |

## 7. 明确不要做的事

- ❌ 不要尝试"修改 WhatsApp 本体"或注入其进程。技术上要越狱，法律上是破解，且 WhatsApp 一更新就废。
- ❌ 不要做"自动点发送"。合规底线，也是唯一能避免"译错自动发给客户"的设计。
- ❌ 不要在 iOS 上试图读别的 App 的聊天内容（只有 macOS 的 AX 能做）。
- ❌ 不要引入 Rust/KMP 作为第一版的依赖。边界已经留好了，等第三端动工再说（D-12）。
- ❌ 不要因为"想支持更多语言"就无限扩 `LanguageDetector` 的停用词表——短句误判的根因是信息量不足，不是词表不够，扩表收益快速衰减。
