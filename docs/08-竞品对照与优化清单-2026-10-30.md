# 08 · 竞品对照与优化清单（2026-10-30）

> 本文回答两个问题：**同类产品都有什么**、**微翻下一步该补什么**。
> 优化项的落地步骤在 `docs/09-开发计划-2026-10-30.md`，决策依据（为什么选这几项）记在 `docs/07` 的 D-55。
> 调研时间：2026-10-30，信息来自各家官网 / 商店页 / 官方文档，链接附在文末。

## 一、竞品都在做什么

### 沉浸式翻译（Immersive Translate，3000 万用户，双语网页翻译标杆）

| 功能 | 说明 |
|---|---|
| 网页双语对照 | 智能识别主内容区，逐段原文/译文对照 |
| **输入框翻译** | 在任意输入框里直接翻，不用复制粘贴 |
| 鼠标悬停翻译 | 悬停即翻指定段落 |
| PDF / EPUB 双语 | 整份文档对照翻译，支持导出 |
| 视频双语字幕 | YouTube 等平台实时字幕 |
| 图片 / 漫画翻译 | OCR 后翻译 |
| 多引擎 + AI | 多家翻译服务 + 大模型 |

### 划词翻译（hcfy.app，老牌划词工具）

| 功能 | 说明 |
|---|---|

| 功能 | 说明 |

| 整页翻译 | 几次点击翻全页 |

| 功能 | 说明 |

| 快捷键自定义 | 三按 Ctrl 查词等手势（沙拉查词） |
| 双语对照 | 网页 / 划词 / 字幕（KISS-Translator） |

### WhatsApp 专用翻译扩展（场景最贴近的同类）

商店里有多款「WhatsApp™ 自动翻译」类扩展，共同点：

- **收件自动翻**：译文直接嵌在消息气泡旁，形成双语对照（微翻已有）；
- **发件自动/手动翻**：把输入框内容翻成对方语言再发（微翻已有，手动触发不烧额度）；
- 悬停翻译、200+ 语种、语音转文字（部分付费 / 订阅制）。

**结论**：在 WhatsApp 翻译这个场景里，微翻的核心闭环（收件双语 + 发件改写 + 降级路由 + 免费额度）
已经对齐同类，且「九家服务商降级 + 额度保护 + 本机解析文档」这几点是付费竞品都没有的。
差距集中在**触发方式的多样性**（右键菜单、快捷键）和**译后体验**（朗读、历史、备选译文）。

## 三、优化项分级

> 分级依据：① 是否贴合「WhatsApp 跨境聊天」主场景；② 免费额度哲学（本机/零成本优先）；
> ③ 两端能否同规格；④ 实现风险。**不是把竞品功能全抄一遍**——输入框边写边译这类烧额度的
> 已经在 D-53 明确不做，视频字幕 / 图片翻译与主场景无关，列入"明确不做"。

### P0 · 本轮就做（2026-10-30）

| # | 优化项 | 为什么 | 成本 |
|---|---|---|---|
| P0-1 | **右键菜单「用微翻翻译」** | 三大竞品全有；WhatsApp 页面里选一段话右键就翻，是最自然的触发方式；零额度成本 | 小：manifest 加权限 + background 建菜单 + 复用划词气泡链路 |
| P0-2 | **键盘快捷键** | hcfy 的 `Ctrl/Cmd+Shift+1` 是很多人留在那个扩展的理由；快捷键补齐"不碰鼠标"的最后一环 | 小：manifest `commands` + background `onCommand` |
| P0-3 | **译文朗读 TTS（两端）** | 语音回复前先听一遍译文语气；用浏览器 / 系统自带语音合成，**零成本不碰翻译额度**；两端同规格 | 中：扩展用 `speechSynthesis`，Android 用 `TextToSpeech`，都是平台内置 |
| P0-4 | 收尾提交「设置页分组折叠」 | 工作区已实现的半成品，先收尾才能干净开新活 | 已写完，差验证 |

### P1 · 下一轮（按价值排序）

| # | 优化项 | 为什么 | 风险 |
|---|---|---|---|
| P1-1 | **上下文连续翻译** | 聊天是强上下文场景：同一段话单独翻和接着上一句翻，结果差很多。给大模型服务带最近 N 条消息，机翻服务不受影响 | 中；要注意隐私（把更多聊天内容发给翻译服务，需设置开关 + 默认关） |
| P1-2 | **常用语 / 翻译历史** | 跨境卖家重复话术多（物流、价格、售后），存一遍以后一键发；沙拉查词的生词本证明了这类需求 | 中；存储 + 管理界面，两端 |
| P1-3 | 备选译文 | DeepL 的差异化体验；LLM 服务可一次要两个版本，机翻服务做不了 | 低；仅对支持的服务展示 |
| P1-4 | 悬停 / 划词气泡支持"固定面板" | hcfy 的钉住体验，长消息阅读更舒服 | 低 |
| P1-5 | 缓存持久化（可选开关） | 现在 300 条内存缓存重启即清；改为可选手动清理，省额度更彻底 | 低；存储增长要设上限 |

### 明确不做 / 后置（理由保留，防止反复）

| 项 | 理由 |
|---|---|
| 输入框边写边译 | 每敲几个字发一次请求，烧免费额度，D-53 已明确不做；保留手动触发 |
| 视频字幕 / 图片 / EPUB | 与 WhatsApp 跨境聊天主场景无关，做了是负担 |
| 整页双语对照 | WhatsApp 是消息流不是文章页，消息级双语已经覆盖 |
| iOS | 仍被 Xcode 阻塞，保持最后做 |

## 四、P0 三项的具体设计

### P0-1 右键菜单

- manifest 增加 `contextMenus` 权限（Firefox 同名兼容）。
- `background.js` 在安装时创建一个菜单：**「用微翻翻译“%s”」**（`contexts: ['selection']`），
  点击后走**与划词气泡完全同一条链路**：把文本投给所在标签页的 pageagent 弹气泡；
  标签页不支持注入（如 chrome:// 页）就打开文本翻译页并带上原文。
- 只建**一个**菜单项，不做子菜单——目标语言、服务都沿用全局设置，设置越少越快。

### P0-2 键盘快捷键

- manifest 增加 `commands`，默认键位（浏览器扩展惯例用 Alt+Shift 系，避开系统占用）：
  - `translate-selection`：`Alt+Shift+T` —— 翻译当前选区（等同右键菜单）
  - `toggle-hover`：`Alt+Shift+H` —— 开 / 关鼠标悬停
  - `open-text-page`：`Alt+Shift+X` —— 打开文本翻译页
- 用户可在 `chrome://extensions/shortcuts` 自改；面板「更多功能」里写明三个默认键位。

### P0-3 译文朗读 TTS（两端同规格）

- **触发点**：划词气泡的译文区、文本翻译页每个译文框（各加一个 🔊 按钮，与复制按钮并排）；
  Android 划词 / 文本页的每个译文行同样加。
- **引擎**：扩展用 `speechSynthesis`（浏览器内置，离线可用）；Android 用 `android.speech.tts.TextToSpeech`（系统内置）。
  都不产生任何网络请求与费用，符合"额度保护"哲学。
- **语言映射**：目标语言代码 → BCP-47 朗读标签（`zh → zh-CN`、`en → en-US`……）。
  这是个纯函数，放 `extension/src/core/tts.js` 与 `android .../core/Tts.kt` 两份同规格实现，**进断言集**。
- 读错不静默：语言不可读时按钮置灰并提示，不用报错弹窗打断。
