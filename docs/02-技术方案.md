# 技术方案

## 1. 总体架构

```
┌──────────────────────── iOS（v0.1） ────────────────────────┐
│                                                             │
│  WeiFan.app              微翻键盘扩展         分享扩展        │
│  ├ 设置/密钥             ├ 读取输入框中文     ├ 收件文本      │
│  ├ 客户档案              ├ 语言芯片          ├ 收件语音      │
│  ├ 术语表                ├ 译 + 原地替换     └ 显示译文      │
│  └ 历史记录              └ 撤销                             │
│         │                      │                  │         │
│         └──────────┬───────────┴──────────────────┘         │
│                    ▼                                        │
│         ┌─────────────────────────────┐                     │
│         │  WeiFanCore（纯 Swift，无 UI）│                    │
│         │  Detection → Glossary →      │                    │
│         │  Routing → Provider → Risk   │                    │
│         └─────────────────────────────┘                     │
│                    │                                        │
│         App Group：设置 / 档案 / 历史                        │
│         Keychain：翻译服务密钥（三 target 共享）              │
└────────────────────┼────────────────────────────────────────┘
                     ▼
      Google Translation / DeepL / DeepSeek / OpenAI Whisper
```

**分层原则**：`WeiFanCore` 里不允许出现 `import UIKit` / `import SwiftUI`。这条边界是将来移植到 Kotlin / Rust 的唯一保障（D-12）。

## 2. 模块职责

| 模块 | 文件 | 职责 | 移植难度 |
|---|---|---|---|
| 语种 | `Language.swift` | 语种枚举、展示名、引擎能力标记 | 极低（纯数据） |
| 检测 | `LanguageDetector.swift` | 本地语言检测：脚本判定 + 拉丁语系停用词打分 | 低（纯算法） |
| 术语 | `Glossary.swift` | 占位符保护与还原 | 低 |
| 路由 | `Routing.swift` | 机翻/大模型决策、风险闸门、文本特征正则 | 低 |
| 服务商 | `Providers.swift` | Google / DeepL / LLM / Whisper 的 HTTP 适配 | 中（各家请求格式） |
| 门面 | `TranslationCore.swift` | 语言解析顺序、术语套用、路由、调用、风险汇总 | 中 |
| 存储 | `Storage.swift` | 设置、客户档案、App Group UserDefaults | 低（各平台等价 API） |

## 3. 关键接口（改动需同步四端）

```swift
// 发件：中文 → 对方语言
func translateForSending(_ text: String,
                         explicitTarget: LanguageCode? = nil,
                         profile: CustomerProfile? = nil,
                         contextSample: String? = nil) async throws -> SendOutcome

// 收件：对方语言 → 中文
func translateIncoming(_ text: String, profile: CustomerProfile? = nil) async throws -> IncomingOutcome

// 语音
func translateVoice(audioURL: URL, languageHint: LanguageCode? = nil) async throws -> IncomingOutcome
```

`SendOutcome` 必须携带：译文、目标语言、路由、服务商、风险原因、术语命中、延迟、**语言来源**（manual / detected / profile / fallback）。最后一项是给用户的解释：键盘上要显示"目标：西班牙语（兜底）"，用户才会相信系统没有瞎猜。

## 4. 发件管道（逐段说明）

```
① 定语言   explicitTarget > detection(置信度≥0.45) > profile.language > 兜底英语
② 术语保护 命中的词 → ⟦0⟧ ⟦1⟧ …，同时记录「原文 → 替换值」
③ 路由     长度>60 或 含数字 → LLM；商务语气且>30字 → LLM；否则机翻
④ 翻译     选服务商：target 支持 DeepL 则 DeepL，否则 Google；LLM 无 key 时回落 Google
⑤ 还原     宽松正则把 ⟦n⟧ 换回术语原文；换不回来就保留占位符（可见的失败 > 静默的错译）
⑥ 风险     金额（硬）/数字/日期/术语命中/长句/低置信度/语言切换
⑦ 落地     直发 = 删除原文+插入译文；需确认 = 显示译文等第二次点击
```

**注意 ②→⑤ 的顺序不可调换**：如果先翻译再做术语替换，模型可能已经把"轻舟"译成"Light Boat"，此时再替换原文会出现中英混杂。

## 5. 提示词（四端共用资产）

位置：`Providers.swift` → `LLMTranslationProvider.systemPrompt`。

要点：
1. 只输出译文，无解释无引号；
2. 语气按 `TranslationStyle` 切换（商务/日常/直译）；
3. **占位符 `⟦数字⟧` 必须原样保留在原位置**——这是术语保护能否成立的前提；
4. 金额、数量、日期、型号逐字对应，不换算不取整；
5. 人名/品牌/型号不音译；
6. 原文已是目标语言则原样返回。

改动提示词后必须回归 A-7（术语保护）与 A-6（金额拦截）两个验收项。

## 6. iOS 工程细节

### 6.1 三个 target

| Target | 类型 | Bundle ID | 关键配置 |
|---|---|---|---|
| WeiFan | app | com.weifan.app | URL scheme `weifan://` |
| WeiFanKeyboard | app-extension | com.weifan.app.keyboard | `com.apple.keyboard-service`，`RequestsOpenAccess = YES` |
| WeiFanShare | app-extension | com.weifan.app.share | `com.apple.share-services`，支持文本 + 1 个文件 |

### 6.2 共享数据

| 数据 | 存放 | 说明 |
|---|---|---|
| 设置、客户档案、历史 | App Group `group.com.weifan.app` 的 UserDefaults | 三个 target 都能读写 |
| 翻译服务密钥 | Keychain，access group `$(AppIdentifierPrefix)com.weifan.shared` | **不能**放 UserDefaults；键盘扩展必须能读到 |

> Keychain 共享是易错点：两个 target 的 entitlements 必须写同一个 access group，且签名时必须包含该 capability，否则键盘里 `SecItemCopyMatching` 返回 `errSecMissingEntitlement`，表现为"键盘能翻译但一直报缺少密钥"。

### 6.3 键盘扩展的硬约束

| 约束 | 数值/表现 | 应对 |
|---|---|---|
| 内存上限 | 约 30–60MB，超了直接被 kill | 不加载模型、不缓存历史、不预取图片；`TranslationHistory` 在键盘里不读 |
| 无 Full Access 时不能联网 | `hasFullAccess == false` | 顶部直接提示去开权限，不静默失败 |
| 必须提供键盘功能 | App Store 审核要求（自用侧载不受限，但将来上架要注意） | 当前只有翻译按钮，上架前需补一个基础字母键盘或改定位 |
| 高度 | 用 `view.heightAnchor` 固定 216pt | 过矮会挤掉预览区 |
| 无法触发宿主 App 的发送 | 只能 `insertText` | 由用户点 WhatsApp 绿色键（D-02） |

### 6.4 文本替换的正确做法

```swift
let before = textDocumentProxy.documentContextBeforeInput ?? ""
for _ in 0..<before.count { textDocumentProxy.deleteBackward() }
textDocumentProxy.insertText(translated)
```

- 用 `before.count`（Character 数）而不是 `utf16.count`，因为 `deleteBackward` 按字素簇删除；
- 必须封顶（代码里用 2000），防止某些输入框返回整段历史文本时把内容删光；
- `documentContextBeforeInput` 在光标之前有选中文本时行为不同，当前不做选区处理（已知限制）。

### 6.5 语音链路（待验证）

分享扩展 `loadFileRepresentation` 给的临时 URL **在回调返回后即失效**，必须先 `copyItem` 到自己的临时目录再上传。代码已按此实现；但 WhatsApp 是否把语音消息以 `public.audio` 暴露给分享扩展，尚未实测（V-02）。

## 7. 服务商与成本

价格随官方调整，以下为撰写时的量级参考，**上线前请以官网为准**：

| 服务 | 免费额度 | 之后价格 | 本项目用途 |
|---|---|---|---|
| Google Cloud Translation | 每月 50 万字符 | 约 $20 / 百万字符 | 兜底机翻 |
| DeepL API Free | 每月 50 万字符 | Pro 约 $8.74/月起 | 中→欧语主力 |
| DeepSeek | 按 token 计费 | 极低（约 ¥1/百万输入 token） | 长句/含数字 |
| OpenAI Whisper | 无 | 约 $0.006/分钟 | 语音转写 |

**估算**：每天 100 条消息、平均 30 字 → 约 9 万字符/月，**基本落在免费额度内**。真正烧钱的是语音：一天 10 条 1 分钟语音 ≈ 每月 300 分钟 ≈ $1.8。

**成本控制手段**（都还没做，按需再加）：
- 相同文本 5 分钟内不重复请求（内存 LRU，10 条）；
- 键盘里"点译才算"，不做边打边译（这是最大的成本节省，也是 D-04 的直接收益）。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 无密钥 | `missingCredential`，键盘状态条提示"去 App 里填密钥" |
| 网络失败 | `transport`，保留原文不替换，允许重试 |
| 4xx/5xx | `badStatus`，展示状态码与响应前 120 字 |
| 返回空 | `emptyResult`，保留原文 |
| 断网 | 同上，**绝不静默替换成空字符串** |

一条铁律：**任何失败都不能导致输入框里的中文消失**。当前实现的顺序是"先拿到译文，再删原文"，不可颠倒。
